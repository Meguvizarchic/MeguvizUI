# P2 可选能力

以下 7 项扩展模块对应 8 个 Maven 制品，均已随 `1.2.0` 发布到 Maven Central 并纳入 `io.github.jichuo1.meguviz:meguviz-bom:1.2.0`。它们默认不进入 `meguviz-ui-core` / `meguviz-ui-widgets` 的传递依赖，消费者按需引入；在源码仓库中通过各自 Gradle 属性开启。

| 模块 | Maven artifactId | 源码 Gradle 属性 | 用途与边界 |
| --- | --- | --- | --- |
| [ui-plan](../ui-plan/README.md) | `meguviz-ui-plan` | `enablePlan` | 纯数据计划，按验证、解析、绑定、挂载分阶段执行；静态页面直接用 DSL 即可。 |
| [ui-codegen-api / ui-codegen](../ui-codegen/README.md) | `meguviz-ui-codegen-api`、`meguviz-ui-codegen` | `enableCodegen` | KSP 根据 `@GenerateUiFactory` 生成直接工厂、typed ref 与 registry 注册入口。 |
| [ui-recycler](../ui-recycler/README.md) | `meguviz-ui-recycler` | `enableRecycler` | 可选 `RecyclerView` 绑定，最多保留 1 个运行中 diff 与 1 个最新待办。 |
| [ui-text](../ui-text/README.md) | `meguviz-ui-text` | `enableText` | 默认关闭的长文本预计算；API 27、短文本与富文本输入回退普通 setter。 |
| [ui-layouts](../ui-layouts/README.md) | `meguviz-ui-layouts` | `enableLayouts` | 受限原生横向行；基于 `LinearLayout`，无特殊性能收益声明。 |
| [ui-prewarm](../ui-prewarm/README.md) | `meguviz-ui-prewarm` | `enablePrewarm` | 可取消的有界主线程分帧预热，复用会话帧驱动，不抢占已启动工作单元。 |
| [ui-frame-shared](../ui-frame-shared/README.md) | `meguviz-ui-frame-shared` | `enableFrameShared` | 同主线程多会话合流帧驱动；单 session 无收益，默认不启用，以控制开销上限为验收指标。 |

在源码中启用全部 7 项并执行主机聚合验证：

```sh
./gradlew -PenableP2=true verifyP2 --no-daemon --max-workers=2
```

`verifyP2` 检查各模块单元测试、lint、制品输出一致性、JVM API 基线及生成器消费样例；完整独立消费者样例见 [p2-consumer](../samples/p2-consumer/README.md)。

## 异步与合流快路径（`1.2.0`）

- **`ui-recycler` 槽位复用**：内部 `LatestWork` 在后台计算进行中时，复用尚未启动的 `pending` 槽并直接替换最新值，不修改正在执行的输入，保持最多 1 个 running 加 1 个 pending；`UiListAdapter.submitList` 的快照数组隔离语义不变，不可将必须保留次数的业务操作放入 latest-wins 列表更新。
- **`ui-text` 与 `ui-prewarm` 复用**：`LatestTextWork` 同步采用 `pending` 与 `reusable` 槽复用（覆盖 `PrecomputedTextBinding.submit` 的先 `invalidate` 再提交模式）；`UiPrewarmer.schedule` 将每单元创建的两个闭包提升为实例字段，避免预热阶段的重复闭包分配。
- 主机探索探针 [LatestWorkProbe.java](../scripts/performance/LatestWorkProbe.java)（2,000 次突发提交，预建输入隔离口径）观测到 owner 线程分配由 33,344 B 降至 1,376 B（不含 adapter 列表快照数组）：

```sh
./gradlew -PenableRecycler=true :ui-recycler:latestWorkProbe --offline --no-daemon --no-configuration-cache
```

## 性能验收基准

[p2-benchmark](../samples/p2-benchmark) 对 7 个模块分别构造同输入 A/B 对照实验（A 为不使用该模块，B 为使用该模块），在前台 `Activity` 中使用不可调试、`speed` AOT 编译构建按 ABBA 交替运行（20 次预热、300 样本，每个样本校验原生 View 结构）。判定阈值固定在 [p2_performance_criteria.toml](../build-logic/verification/p2_performance_criteria.toml)：

- 非收益类模块（`plan`、`codegen`、`layouts`、`frame-shared`）使用**配对比值**（`paired-ratio`）：按每对样本的 `B / A` 计算中位数与 bootstrap 95% CI，要求 CI 上界不超过 `max_ratio`（抵消调频与大小核迁移漂移）。
- 收益类模块（`recycler`、`text`、`prewarm`）使用**中位数之比**（`median-ratio`）：两组各自独立重采样，要求 CI 上界低于 `max_ratio`。

```sh
./gradlew -PenableP2=true verifyP2Performance -Pp2PerformanceSerial=<adb serial> -PallowDeviceInstall=true --no-daemon --max-workers=2
```

执行要求：必须为物理真机（脚本拒绝模拟器），热状态不超过 `1`。结果写入 `build/reports/gates/p2-performance.json`。

2026-10-27 按源码指纹 `431d13…` 在 PMA110（Android 17 / API 37，arm64，热状态 0/0）上的实测记录（每组 300 样本）：

| 模块 | 场景 | 统计方法 | A 中位 | B 中位 | B/A | 95% CI | 达标门槛 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `plan` | 48 节点页面构造 | 配对 | 3.49 ms | 3.71 ms | 1.05 | 1.03–1.07 | 上界 ≤ 1.25 | 通过 |
| `codegen` | 64 个视图注册挂载 | 配对 | 4.42 ms | 4.48 ms | 1.00 | 0.99–1.02 | 上界 ≤ 1.10 | 通过 |
| `recycler` | 16 次突发提交、2000 项，到最终列表应用 | 中位数比 | 9.09 ms | 3.37 ms | 0.37 | 0.34–0.41 | 上界 < 0.90 | 通过 |
| `text` | 3000 字纯文本，主线程应用+测量+布局 | 中位数比 | 1.07 ms | 0.74 ms | 0.69 | 0.68–0.73 | 上界 < 0.90 | 通过 |
| `layouts` | 8 行构造+测量+布局 | 配对 | 9.39 ms | 9.58 ms | 1.01 | 0.99–1.02 | 上界 ≤ 1.10 | 通过 |
| `prewarm` | 48 行页面首次切换帧 | 中位数比 | 7.63 ms | 2.45 ms | 0.32 | 0.32–0.33 | 上界 < 0.50 | 通过 |
| `frame-shared` | 32 个 session 共享帧分发 | 配对 | — | — | — | — | 上界 ≤ 1.25 | 待物理机测量 |

关键事实说明：

- `recycler` 在将稳定 ID 校验与去重移至后台 diff 并改用 `LongArray` 后，`B/A` 从 3.47 降至 1.10；增加不可变模型构造器（仅一次数组拷贝）后降至约 0.37（突发提交期间主线程耗时约 0.14 ms，官方 `ListAdapter` 约 0.03 ms）。模型含可变字段时仍须使用带 `snapshotItem` 的构造器。
- `text` 仅加速主线程应用与测量路径；后台预计算导致文本就绪晚约 1.1 ms。
- `prewarm` 将页面构造分散至切换前的 12 个平台帧执行，单单元耗时中位约 1.1 ms。
- 跨轮次对比应只参考同轮内 `B/A` 比值，避免因设备状态差异比较不同轮次的绝对耗时。

## 设备行为矩阵

`verifyP2Matrix`（[p2_matrix.py](../build-logic/verification/p2_matrix.py)）在 [p2-matrix](../samples/p2-matrix) 上运行 16 项仪器测试、通过 `adb` 驱动进程死亡恢复并校验 R8 混淆后的独立消费者。字号、RTL、语言和深色模式均通过应用内配置覆盖。

```sh
./gradlew -PenableP2=true verifyP2Matrix -Pp2MatrixSerial=<adb serial> -PallowDeviceInstall=true --no-daemon --max-workers=2
```

2026-10-27 在旧指纹 `431d13…` 下（当时含 6 模块共 15 项矩阵用例与 13 项仪器用例；新增 `frame-shared` 后总计增至 16 项仪器测试与 17/16 类矩阵覆盖）的历史运行结果如下：

| 设备 | 6 模块仪器测试 | 行为矩阵 |
| --- | --- | --- |
| PMA110 真机（OPPO/ColorOS，Android 17 / API 37） | 13/13 | 17/17 |
| 隔离模拟器 API 27 | 13/13 | 17/17 |
| 隔离模拟器 API 29 | 13/13 | 17/17 |

已解决的矩阵边界记录：
- **`ui-text` RTL 方向迟到修复**：预计算完成时若 `TextView` 刚解析出 RTL 方向导致 `PrecomputedText.Params` 变化，现会以新参数重算最新文本（最多重试 2 次），用尽或再变时回退普通 setter，确保文本不为空白。
- **冷启动超预算**：真机冷启动首个预热单元若超过 2 ms 默认预算将被丢弃并回退至打开页面时懒建，符合预期。

## 人工无障碍检查清单

`verifyP2Matrix` 已自动核对无障碍节点树（标签、48 dp 点击区、标题、列表集合信息、阅读顺序、Tab / D-pad 遍历与 Enter 激活）。以下项目须开启 TalkBack 在真机手工实听确认（每项记录设备、系统版本、TalkBack 版本、实际朗读及截图）：

| 界面 | 操作 | 期望 |
| --- | --- | --- |
| 标题与 plan 行 | 从顶部逐项右滑 | 先读标题并播报“标题”，随后按序播报 plan 两行 |
| 生成标签与长文本 | 右滑到长文本 | 完整朗读混合中英文与阿拉伯文段落，无截断或重复 |
| 原生行 | 右滑经过两行 | 每行先读标签再读按钮并播报“按钮”；RTL 下顺序镜像为“标签 → 按钮” |
| 打开页面 | 双击 Open page | 读出新页面首行；预热就绪与懒建两种路径播报一致 |
| 列表 | 进入列表并双击 Toggle | 进入时播报总行数；切换后播报新状态且焦点留在同一行 |
| 旋转与重建 | 焦点停在 Pair 时旋转屏幕 | 旋转后 TalkBack 焦点留在 Pair 或落在可预期位置 |
| 字号放大 | 系统字号调至最大后重测 | 无截断、点击区可达、朗读内容不变 |

## 适用范围与验证说明

- KSP 处理器仅参与编译期；`RecyclerView` 依赖仅属于 `ui-recycler`。
- 主机单元测试通过、仪器 APK 编译成功或单机（PMA110 / 无 R8 分离层级）基准记录均不能替代目标应用在自身负载、OEM 机型及开启 R8 后的设备回归与性能评估。
- `frame-shared` 性能准则设定为 `bounded-overhead`（允许得出“单场景不值得启用”的结论），尚缺物理机最新测算数据，引入前应实测多会话对比。

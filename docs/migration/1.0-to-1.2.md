# 从 1.0.0 迁移到 1.2.0

本文说明已发布的 `1.0.0` 与当前已上线的 `1.2.0` 之间的 API 和模块变化，并提供平滑升级步骤。

## 版本与发布口径

| 项目 | 值 | 来源 |
| --- | --- | --- |
| 起始基线版本 | `1.0.0`（tag `v1.0.0`） | `api/legacy/1.0.0/` |
| 当前发布版本 | `1.2.0`（Maven Central，groupId `io.github.jichuo1.meguviz`） | `gradle.properties` |
| 统一版本管理 | `io.github.jichuo1.meguviz:meguviz-bom:1.2.0`（管理家族 33 个 `1.2.0` 制品，含 MeguvizUI 12 个） | Maven Central |
| 未上 Central 例外 | `meguviz-ui-lumen-bridge`（仅可源码启用 `-PenableLumen=true` 本地构建） | `ui-lumen-bridge/build.gradle.kts` |
| API 兼容性门禁 | `api/public-api.txt` 为当前公开描述符快照；`verifyLegacyAbi` 验证其为 `1.0.0` 描述符的严格超集 | `docs/development.md` |

## 1. 变化总览

| API / 模块 | `1.0.0` | `1.2.0` | 迁移动作 |
| --- | --- | --- | --- |
| `UiSession` 基础接口（mount/borrow/transfer/inflate/bind/release/detach/reattach/close/requestClose 等） | 已有 | 保留 | 无需改动 |
| `ViewRef.get` / `ViewRef.token` | 已有 | 保留 | 无需改动 |
| `ViewRef.bind(PropertySpec)` | 无 | **新增**（`Identity.kt`） | 可选改用流式写法 |
| `PropertySpec` / `Properties`（5 个内置 spec） | 已有 | 保留 | 无需改动 |
| `ParentScope` / `FrameScope` / `LinearScope` / `Framework` / `*Params` | 已有 | 保留 | 无需改动 |
| `ParentScope` 的 `String` key 重载 | 无 | **新增**（`Widgets.kt`） | 可选省略 `ViewKey(...)`；Java 调用方必需 |
| `Activity.openMeguvizUi()` / `UiScope` | 无 | **新增**（`UiScope.kt`） | 常规 Activity 推荐采用 |
| `UiScheduler.submitState` / `submitCommand` / `submitBatch(List)` | 已有 | 保留 | 无需改动 |
| `UiScheduler.submitBatch(vararg)` | 无 | **新增**（`UiScheduler.kt`） | 可选简化写法 |
| `UiScheduler.submitStates(List<StateUpdate>)` / `StateUpdate` | 无 | **新增**（`UiScheduler.kt`、`StateUpdate.kt`） | 同语义多状态批量合并提交 |
| `OwnerThreadDispatcher` / `submitStateAsync` / `submitCommandAsync` | 无 | **新增**（`UiScheduler.kt`、`UiSession.kt`） | 跨线程合并提交时采用 |
| `UiScheduler.pause` / `resume` / `recover` / `discardInvalid`、`SchedulerState`、`SubmitResult` | 已有 | 保留 | 无需改动 |
| `RegistrySnapshot.install` / `FactoryRegistration` / `ExtensionDescriptor` | 已有 | 保留 | 无需改动 |
| `ViewRestoration` / `RestorationSnapshot` / `StateCodec` / `StableIdStore` | 已有 | 保留 | 无需改动 |
| `ui-widgets` | 已有 | 保留 | 无需改动 |
| `ui-plan` / `ui-codegen-api` / `ui-codegen` / `ui-recycler` / `ui-text` / `ui-layouts` / `ui-prewarm` | 已有 | 保留 | 升级版本号或使用 BOM |
| `ui-frame-shared` | 无 | **新增 Central 制品** | 多会话共享帧源时按需添加 |
| `ui-ref-bridge` | `1.0.0` 已发布 | **`1.2.0` 已随 BOM 发布** | 跟随升级到 `1.2.0` |
| `ui-android-bridge` | 未随 `1.0.0` 发布 | **`1.2.0` 已随 BOM 发布** | 需要 `WindowSession` 联动时可从 Central 引入 |
| `ui-lumen-bridge` | 未上 Central | 仍未上 Central | 仅可源码构建 `-PenableLumen=true` |

`UiScheduler` 新增第 8 个可选参数 `dispatcher`，同时**保留原 7 参次级构造器**及相同默认值，确保以 `1.0.0` 编译的旧 Kotlin/Java 二进制调用方直接链接而不出现 `NoSuchMethodError`（由 `LegacyBinaryShapeTest` 锁定）。

## 2. `1.0.0` 既有 API 的完全保留

以下入口在 `1.0.0` 与 `1.2.0` 中均完全一致，升级时无需修改现有调用代码：

- **会话与挂载**：`UiSession`、`CreationEnvironment`、`ViewKey`、`ComponentType`、`ParentPolicy`、`NativeOwnership`、`ViewFactory`；`mount` / `borrow` / `transfer` / `inflate` / `bind` / `reserveProperties` / `click` / `onRelease` / `onClose` / `rebind` / `detach` / `reattach` / `release` / `requestClose` / `close`。
- **引用与属性**：`ViewRef.get` / `token`、`BindingToken`、`PropertySpec`、`PropertyBinding`、`EffectMask`、`PropertyOwnership`；`Properties.plainText` / `richText` / `textColor` / `visibility` / `checked`。
- **布局与调度**：`ParentScope` / `FrameScope` / `LinearScope`、`Framework`、`linearParams` / `frameParams`、`Dp` / `Sp`；`UiScheduler` 原 7 参构造及同步提交通道、`UiFrameDriver`、`FrameBudget`、`ChoreographerFrameDriver`。
- **恢复、扩展与 P2 模块**：`ViewRestoration`、`StateCodec`、`StableIdStore`、`RegistrySnapshot`；`ui-plan`、`ui-codegen-api`、`ui-codegen`、`ui-recycler`、`ui-text`、`ui-layouts`、`ui-prewarm`。

## 3. `1.2.0` 新增能力与升级写法

### 3.1 `ViewRef.bind(PropertySpec)`

- **位置**：`ui-core/src/main/kotlin/io/github/jichuo1/meguviz/ui/Identity.kt`
- **1.0.0 写法**：`val binding = session.bind(ref, Properties.plainText())`
- **1.2.0 可选简写**：`val binding = ref.bind(Properties.plainText())`（纯委托给 `session.bind`，校验与清理完全相同）。

### 3.2 `Activity.openMeguvizUi()` 与 `ParentScope` 字符串 key 重载

- **位置**：`ui-widgets/.../UiScope.kt`、`ui-widgets/.../Widgets.kt`
- **1.0.0 写法**：手动创建 `FrameLayout` + `UiSession` + `FrameScope`，在 `onDestroy` 调 `session.close()`，所有节点 key 须显式传 `ViewKey("...")`。
- **1.2.0 推荐写法**：
  ```kotlin
  val ui = openMeguvizUi() // Java 使用 UiScopeKt.openMeguvizUi(activity)
  setContentView(ui.root)
  val title = ui.scope.text("title", frameParams()) { text = "Ready" }
  title.bind(Properties.plainText()).submit("Updated")
  ```
- **说明**：`openMeguvizUi()` 仅用于普通 `Activity`；带有 `WindowSession` 的场景仍使用 `AndroidUiBinding.open(window, root)`。字符串 key（`"title"`）与 `ViewKey("title")` 指向同一键名并共享冲突校验，同时使 Java 代码能直接挂载控件。

### 3.3 `UiScheduler.submitStates`、`submitBatch(vararg)` 与异步提交

- **同语义状态批次**：`UiScheduler.submitStates(updates: List<StateUpdate>)` 将同一语义集合的状态更新作为一次提交单元，执行一次 owner 校验与一次帧请求，批内按槽去重；超出 `stateCapacity` 时保留已入队的前序条目而不回滚。
- **不定长批次重载**：`submitBatch(vararg operations: ScheduledOperation)` 与原 `List` 重载具有相同入队与快照语义。
- **跨线程合并提交**：`UiSession.submitStateAsync(slot, isValid, action)` 与 `submitCommandAsync(isValid, action)`（对应 `UiScheduler` 同名方法）允许从后台线程非阻塞写入有界 handoff，同一热槽在合并前即折叠，N 次更新仅产生 1 次 owner 派发。手动构造 `UiScheduler` 且未传 `OwnerThreadDispatcher` 时，异步入口固定返回 `Rejected(CLOSED)`。

### 3.4 `ui-frame-shared` 模块

- **位置**：`ui-frame-shared`（`SharedFrameDriver`、`FrameSource`、`ChoreographerFrameSource`）。
- **用途**：把同一主线程上多个 `UiSession` 的帧请求合并成一次平台帧回调（单会话场景无收益）。关闭顺序须先关闭各 `UiSession`，最后关闭 `SharedFrameDriver`。

## 4. 升级步骤

1. **接入 BOM 或更新版本号**：
   ```kotlin
   dependencies {
       val bom = platform("io.github.jichuo1.meguviz:meguviz-bom:1.2.0")
       implementation(bom)
       implementation("io.github.jichuo1.meguviz:meguviz-ui-widgets")
       // 若使用 KSP 代码生成，须同时传入 ksp(bom) 与 compileOnly(bom)
   }
   ```
   > 确认工程 `compileSdk >= 37`、`minSdk >= 27`、JDK `17` 与 Kotlin `2.3+`（建议 `2.4.21`）。

2. **按需启用新增接口**：
   - 可将常规 Activity 的手工装配替换为 `openMeguvizUi()`；
   - 可将后台 `Handler.post { ... }` 更新替换为 `ui.submitStateAsync`；
   - 原有 `1.0.0` 调用可全部保留不动，分页面逐步简化。

3. **升级桥接依赖**：
   - `meguviz-ui-ref-bridge` 与 `meguviz-ui-android-bridge` 均已纳入 `meguviz-bom:1.2.0`，直接从 Maven Central 解析即可。
   - `meguviz-ui-lumen-bridge` 仍需从源码仓库通过 `-PenableLumen=true publishCandidate` 构建后在本地 Maven 消费。

## 5. `1.2.0` 运行时行为差异

以下改动不改变公开签名，但影响帧调度与属性读回行为：

- **API 33+ 真实帧 deadline 感知**：`ChoreographerFrameDriver` 在 API 33 及以上版本使用 `postVsyncCallback`，复制 `preferredFrameTimeline.deadlineNanos`（`estimated = false`）；`UiScheduler.drain` 预算取 `min(maxFrameWorkNanos, deadline - started - 1ms)`。API `<= 32` 保持 `estimated = true` 与固定预算。
- **`FrameBudget` 严格构造校验**：声明 `estimated = false` 时必须提供非空 `deadlineNanos`，否则在构造期抛出 `IllegalArgumentException`。
- **状态条目与清理优化**：同槽重提原地复用内部 `StateEntry`；`rebind` / `releaseNode` 批量抑制重复 `discardInvalid()` 扫描；`discardInvalid` 命令队列改用逻辑标记加一次 `O(C)` 压实。
- **`PropertyBinding.apply` 读回收敛**：`SHARED_READ` / `ALWAYS_WRITE` 不再执行不被读取的写后读回或多余快照。

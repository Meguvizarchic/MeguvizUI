# 从 1.0.0 迁移到源码 1.2.0

本文说明已发布的 `1.0.0` 与当前源码 `1.2.0` 之间的 API/模块差异，并给出迁移步骤。

**版本口径**

| 项目 | 值 | 来源 |
| --- | --- | --- |
| 已发布版本 | `1.0.0`（Maven Central，groupId `io.github.jichuo1.meguviz`） | `README.md`、`docs/installation.md` |
| 源码版本 | `1.2.0`，**尚未发布** | `gradle.properties` 的 `meguviz.version=1.2.0` |
| 1.0.0 发布标签 | `v1.0.0`（提交 `cbbaf73`，2026-10-27） | `git tag` |
| API 基线 | `api/public-api.txt`（当前源码候选基线，不是历史稳定版二进制兼容证明） | `docs/development.md` |

**重要声明**

- 下文「源码候选」指存在于当前源码、但不在 `v1.0.0` 发布标签中、尚未发布到 Maven Central 的 API/模块。在 1.2.0 正式发布前不可依赖。
- 已发布的 1.0.0 制品不会以不同内容覆盖（`docs/installation.md`）。
- 单元测试通过不等于设备行为已验收；发布门禁 `release` 仍为 blocked。

## 1. 结论速览

| API / 模块 | 1.0.0 | 源码 1.2.0 | 迁移动作 |
| --- | --- | --- | --- |
| `UiSession`（mount/borrow/transfer/inflate/bind/release/detach/reattach/close/requestClose 等） | 已有 | 保留 | 无需改动 |
| `ViewRef.get` / `ViewRef.token` | 已有 | 保留 | 无需改动 |
| `ViewRef.bind(PropertySpec)` | 无 | **源码候选**（`Identity.kt`） | 可选采用 |
| `PropertySpec` / `Properties`（5 个内置 spec） | 已有 | 保留 | 无需改动 |
| `ParentScope` / `FrameScope` / `LinearScope` / `Framework` / `*Params` | 已有 | 保留 | 无需改动 |
| `UiScheduler.submitState` / `submitCommand` / `submitBatch(List)` | 已有 | 保留 | 无需改动 |
| `UiScheduler.submitBatch(vararg)` | 无 | **源码候选**（`UiScheduler`） | 可选采用 |
| `UiScheduler.submitStates(List<StateUpdate>)` / `StateUpdate` | 无 | **源码候选**（`UiScheduler`、`StateUpdate`） | 可选采用 |
| `UiScheduler.pause/resume/recover/discardInvalid`、`SchedulerState`、`SubmitResult` | 已有 | 保留 | 无需改动 |
| `RegistrySnapshot.install` / `FactoryRegistration` / `ExtensionDescriptor` | 已有 | 保留 | 无需改动 |
| `ViewRestoration` / `RestorationSnapshot` / `StateCodec` / `StableIdStore` | 已有 | 保留 | 无需改动 |
| `ui-widgets` | 已有 | 保留 | 无需改动 |
| `ui-ref-bridge` | 1.0.0 已发布 | 1.2.0 源码（上游 1.2.0） | 跟随上游 |
| `ui-android-bridge` / `ui-lumen-bridge` | 未发布到 Central | 未发布到 Central | 不能从 Central 解析 |
| `ui-plan` / `ui-codegen-api` / `ui-codegen` / `ui-recycler` / `ui-text` / `ui-layouts` / `ui-prewarm` | 已有（v1.0.0 标签内） | API 基线不变 | 无需改动 |
| `ui-frame-shared` | **无**（v1.0.0 标签不含） | **源码候选** | 需要时新增 |
| `Activity.openMeguvizUi()` / `UiScope` | 无 | **源码候选** | 需要时采用 |
| `OwnerThreadDispatcher` / `submitStateAsync` / `submitCommandAsync` | 无 | **源码候选** | 跨线程提交时采用 |

API 基线比较：`git diff v1.0.0 HEAD -- api/public-api.txt` 只显示新增，没有签名删除或修改。本轮新增包括 `ViewRef.bind`、`StateUpdate`、`submitStates`、`submitBatch(vararg)`、`OwnerThreadDispatcher`、`UiScheduler.submitStateAsync` / `submitCommandAsync`、`UiSession.submitStateAsync` / `submitCommandAsync`、`UiScope` 与 `Activity.openMeguvizUi()`。

`UiScheduler` 构造器增加了第 8 个参数 `dispatcher`，同时**保留原来的 7 参构造器**（内部以 `dispatcher = null` 委托，行为即改动前的主线程独占），所以旧的二进制调用方仍然链接得到。

## 2. 1.0.0 已有的 API（不需要迁移）

以下入口在 `v1.0.0` 发布标签中已存在，并在 1.2.0 源码中保留：

- **会话与挂载**：`UiSession`、`CreationEnvironment`、`ViewKey`、`ComponentType`、`ParentPolicy`、`NativeOwnership`、`ViewFactory`；`UiSession.mount` / `borrow` / `transfer` / `inflate` / `bind` / `reserveProperties` / `click` / `onRelease` / `onClose` / `rebind` / `detach` / `reattach` / `release` / `requestClose` / `close`。
- **引用与属性**：`ViewRef.get` / `token`、`BindingToken`、`PropertySpec`、`PropertyBinding`、`EffectMask`、`PropertyOwnership`；`ui-widgets` 的 `Properties.plainText/richText/textColor/visibility/checked`。
- **布局**：`ParentScope` / `FrameScope` / `LinearScope`、`Framework` 的 `text/edit/button/image/linear/frame/scroll` 与 `*Factory`、`linearParams`/`frameParams`、`Dp`/`Sp`。
- **调度**：`UiScheduler` 构造与 `submitState` / `submitCommand` / `submitBatch(List)` / `pause` / `resume` / `recover` / `discardInvalid`；`SchedulerState`、`SubmitResult`、`ScheduledOperation`、`SchedulerFailure`、`SchedulerCounters`；`UiFrameDriver`、`FrameBudget`、`FrameTicket`、`ChoreographerFrameDriver`。
- **恢复与扩展**：`ViewRestoration`、`RestorationSnapshot`、`ViewPresentation`、`StateCodec`、`StableIdStore`、`NodeIdentity`、`StateValue`；`RegistrySnapshot`、`FactoryRegistration`、`ExtensionDescriptor`、`ResolvedBinding`。
- **P2 模块**：`ui-plan`、`ui-codegen-api`、`ui-codegen`、`ui-recycler`、`ui-text`、`ui-layouts`、`ui-prewarm`。这些模块在 `v1.0.0` 标签中已存在，且各自 `api/*.txt` 基线与当前源码一致（无签名变化）。

因此，按 JVM API 基线只增不删，1.0.0 的应用代码在 1.2.0 源码上应可编译；升级主要是版本号与依赖坐标变化。API 基线只覆盖 JVM 描述符，不包含源码兼容性的全部维度，升级后仍应重新编译并验证。

## 3. 源码 1.2.0 新增候选（尚未发布）

### 3.1 `ViewRef.bind(PropertySpec)`

- **位置**：`ui-core/src/main/kotlin/io/github/jichuo1/meguviz/ui/Identity.kt`
- **签名**：`fun <T> bind(property: PropertySpec<V, T>): PropertyBinding<V, T>`
- **语义**：`session.bind(ref, property)` 的纯委托成员；所有权、生命周期、属性冲突检查与清理注册完全由 `UiSession.bind` 执行，不跳过任何步骤。
- **1.0.0 写法**：`val binding = session.bind(ref, Properties.plainText())`
- **1.2.0 可选写法**：`val binding = ref.bind(Properties.plainText())`
- **状态**：源码候选，尚未发布。

### 3.2 `UiScheduler.submitBatch(vararg)`

- **位置**：`UiScheduler`
- **签名**：`fun submitBatch(vararg operations: ScheduledOperation): SubmitResult`
- **语义**：与 `submitBatch(List)`（`UiScheduler`，1.0.0 已有）相同的准入、快照与 FIFO 合同；vararg 重载会复制输入数组，准入后调用方修改数组不影响队列。
- **1.0.0 写法**：`session.scheduler.submitBatch(listOf(op1, op2))`
- **1.2.0 可选写法**：`session.scheduler.submitBatch(op1, op2)`
- **状态**：源码候选，尚未发布；List 重载保留，1.0.0 代码不受影响。

### 3.3 `UiScheduler.submitStates(List<StateUpdate>)` 与 `StateUpdate`

- **位置**：`UiScheduler`；`StateUpdate`
- **签名**：
  ```kotlin
  class StateUpdate(val slot: Any, val isValid: () -> Boolean = { true }, val action: () -> Unit)
  fun submitStates(updates: List<StateUpdate>): SubmitResult
  ```
- **语义**：把「同语义集合」的状态更新作为一次单元提交：一次 owner 校验、一次帧请求、批内按槽去重；逐条准入与重复调用 `submitState` 等价，最后一条生效。容量超限时，已准入的前序条目保留在队列中，不 rollback。
- **1.0.0 写法**：循环调用 `submitState(slot, isValid, action)`。
- **1.2.0 可选写法**：构造 `List<StateUpdate>` 一次提交。
- **状态**：源码候选，尚未发布。

### 3.4 `ui-frame-shared` 模块

- **状态**：**源码候选**。`v1.0.0` 发布标签（`cbbaf73`）的模块列表不含 `ui-frame-shared`；该模块在 1.2.0 源码线中新增（提交 `686d23b`，2026-11-05）。
- **入口**：`SharedFrameDriver(source, owner, ownerCheck)`、`FrameSource`、`ChoreographerFrameSource`。
- **用途**：把同一 owner 线程上多个 `UiSession` 的帧请求合并成一次平台帧回调；单 session 场景没有收益。
- **启用**：Gradle 属性 `-PenableFrameShared=true`，依赖 `meguviz-ui-frame-shared`。
- **文档口径提醒**：`README.md` 当前把 `ui-frame-shared` 列入「已随 1.0.0 发布到 Central」的 P2 表，这与 `v1.0.0` 标签不一致；`docs/installation.md` 也明确「已发布的版本不会以不同内容覆盖」。升级前请以 Maven Central 的实际制品为准，不要假设 1.0.0 已包含该模块。

### 3.5 `Activity.openMeguvizUi()` / `UiScope`（源码候选）

- **位置**：`ui-widgets/src/main/kotlin/io/github/jichuo1/meguviz/ui/widgets/UiScope.kt`（`UiScope` 与 `openMeguvizUi`）
- **状态**：**源码候选，未发布**。不在 `v1.0.0` 标签中，消费 1.0.0 时不可用；实现可能随候选继续变化。
- **语义**：一行创建 root `FrameLayout` + `UiSession` + `FrameScope`，并在 Activity 销毁时自动关闭会话；幂等，非主线程或已销毁 Activity 直接抛错。
- **1.0.0 写法**：手工 `FrameLayout` + `UiSession(CreationEnvironment(activity))` + `FrameScope(session, root)`，并在 `onDestroy` 调 `session.close()`。
- **1.2.0 可选写法**：
  ```kotlin
  val ui = openMeguvizUi()
  setContentView(ui.root)
  val title = ui.scope.text(ViewKey("title"), frameParams()) { text = "Ready" }
  title.bind(Properties.plainText()).submit("Updated")
  ```
- **注意**：该入口只适用于普通 `Activity`；需要 `WindowSession` 时使用 Android 桥的 `AndroidUiBinding.open(window, root)`。

## 4. 迁移步骤

1. **升级依赖版本**（1.2.0 发布后）：
   ```kotlin
   implementation("io.github.jichuo1.meguviz:meguviz-ui-widgets:1.2.0")
   ```
   普通应用依赖 widgets 即可，它会传递依赖 core。P2 模块按需添加。

2. **兼容性检查**：
   - 按 JVM API 基线只增不删，1.0.0 代码应可编译；升级后仍应重新编译验证。
   - 运行 `api/` 基线比较与 `integration/compile-fixtures` 正负编译案例，确认没有依赖被移除的签名。

3. **可选采用新 API**（按需，不强制）：
   - `session.bind(ref, spec)` → `ref.bind(spec)`；
   - `submitBatch(listOf(...))` → `submitBatch(...)`；
   - 多次 `submitState` → 一次 `submitStates(List<StateUpdate>)`；
   - 手工装配会话 → `openMeguvizUi()`（仅普通 Activity）。

4. **P2 模块**：
   - `ui-plan`/`ui-codegen`/`ui-recycler`/`ui-text`/`ui-layouts`/`ui-prewarm` 沿用 1.0.0 用法。
   - 如需共享帧驱动，新增 `meguviz-ui-frame-shared` 并显式启用 `-PenableFrameShared=true`；关闭顺序为先各 session，再 `SharedFrameDriver`。

5. **桥**：
   - `ui-ref-bridge`：1.0.0 已发布；1.2.0 源码对应上游 `meguviz-ref-core` 1.2.0，跟随上游版本。
   - `ui-android-bridge` / `ui-lumen-bridge`：上游尚未发布到 Central，仍不能在默认仓库解析；需按 `docs/bridges/importing-candidates.md` 准备固定哈希的候选。

## 5. 源码 1.2.0 的行为差异

这些变化不改变公开签名，但会影响帧调度与性能语义：

- **默认帧驱动 deadline 感知**：`ChoreographerFrameDriver` 在 API 33+ 改用 `postVsyncCallback`，复制 `preferredFrameTimeline.deadlineNanos`（`estimated=false`）；API ≤32 保持 `estimated=true`、固定预算（`ChoreographerFrameDriver.kt`、`:58-82`）。
- **派生工作预算**：`estimated=false` 时预算取 `min(maxFrameWorkNanos, deadline - started - 1ms)`，为 traversal/draw 留尾部；`estimated=true` 时只用固定预算（`UiScheduler`）。
- **`FrameBudget` fail-closed**：`estimated=false` 必须有非空 `deadlineNanos`，否则构造即拒绝（`UiFrameDriver.kt`）。
- **调度器内部优化**：状态条目复用、`submitStates`、`discardInvalid` 去复制；公开语义与失败报告不变（`docs/scheduling.md`）。
- **`PropertyBinding.apply` 读回收敛**：`SHARED_READ`/`ALWAYS_WRITE` 不再做不被读取的 read-back/snapshot；该行为依赖真实 View，需设备回归（`docs/development.md`）。
- **共享帧驱动语义**：多 session 合流、票据只取消自身请求、单 client 非 `Error` 异常不阻断其他 client、`Error` 在扇出后重抛（`ui-frame-shared/README.md`）。

## 6. 验证与门禁

- `verifyHost` 覆盖核心合同、lint、示例构建、API 基线比较与依赖边界；可选桥开启时增加对应模块验证。
- `verifyReleaseCandidate` 是额外的完整验收门禁；公开源码不附带私有设备/性能记录，因此默认 host 成功不能使发布门禁通过。
- 截至当前 `PROJECT_STATE.json`：`host=passed`、`p2-host=passed`、`p2-consumer=passed`、`p2-performance=passed`，但 `device=blocked`、`release=blocked`、`performance=blocked`、`r8=blocked`、`profile-android/lumen/ref=blocked`。
- 迁移到 1.2.0 后，涉及真实 View 的行为（属性读回、帧预算、共享驱动）需要设备矩阵与性能准入重新验证。

## 7. BIL / Hikage 迁移（独立工作流）

BIL 从 Hikage 迁移到 MeguvizUI 是**独立的消费者工作流**，不属于 1.0.0 → 1.2.0 的 API 迁移。状态如下（来源：`PROJECT_STATE.json`、`integration/bil/`）：

| 项目 | 状态 | 证据 |
| --- | --- | --- |
| Host 迁移 | 通过（4098 测试、0 失败、debug APK、release R8、lint） | `integration/bil/full-host-receipt.json` |
| 迁移范围 | 21 个 Hikage import 文件、453 个工厂位置、451 个 LP 位置已逐项映射 | `integration/bil/full-migration-map.json` |
| Hikage 依赖退出 | 依赖图、debug/R8 DEX 已退出 Hikage | `integration/bil/dependency-closure-final.json` |
| 设备/视觉/性能/回退 | **blocked**（未验收） | `integration/bil/v1-exit-matrix.json`、`PROJECT_STATE.json` 的 `gate_status.bil-full=blocked` |
| 版本口径 | 上述 host 证据基于 MeguvizUI core **1.0.0** 候选 | `integration/bil/full-host-receipt-v1.0.0.json` |

`v1-exit-matrix.json` 的 `release_ready` 为 `false`，剩余项包括真机/OEM 行为与视觉几何、A/B/C/D/E 性能样本、实际进程恢复与回退演练、页面级旧/新后端 flag（未实现，当前只有应用版本回退）。1.2.0 源码候选的 BIL 复验尚未记录。
